## 0. Что значит «полностью рабочий MVP»

### Золотой путь (минимум этого прогона)

1. Гость открывает лендинг → регистрируется (первый пользователь = `admin`).
2. Админ открывает **Админ → Модели ИИ** (или Инструменты → Модели ИИ) и задаёт провайдера + модели + дефолты инструментов (`agent`, `notes`, `image`, `tts`, …).
3. Если ИИ не настроен — чат и генерации **ясно говорят по-русски**, что нужно настроить провайдера. Не падают стеком.
4. Пользователь создаёт воркспейс (книга / фильм / музыка / приложение / универсальный).
5. Во вкладке **Чат** воркспейса пишет задачу. Агент создаёт **хотя бы один персистентный артефакт** в этом воркспейсе (заметка / документ / сущность / картинка / озвучка — в зависимости от типа).
6. Пользователь открывает соответствующие вкладки — видит **те же данные из БД**, не мок.
7. Экспортирует что-то реальное: zip воркспейса / WAV из DAW / WebM раскадровки / zip кода.

### Контракты модулей (если вкладка видна)

| Модуль | Полезное действие MVP |
|---|---|
| Чат | Диалог + инструменты оркестратора в скоупе воркспейса; ошибки по-русски |
| Воркспейсы | CRUD списка из `/api/workspaces`; открытие оболочки |
| Заметки воркспейса | Создать/прочитать заметку, связанную через `NoteLink` |
| Блокнот | Глобальные заметки + анализ (ASR/LLM) — уже есть |
| Документы | Рукопись с автосохранением, версии, сущности, портрет, аналитик |
| Изображения | Промпт → Artifact `image` в галерее |
| Дизайн | Мудборд/палитра из **реальных** image-артефактов (не Photoshop) |
| Аудио | TTS → артефакт; DAW save/load; экспорт WAV |
| Видео | Сцены сценария + кадр + TTS + сборка WebM (Ken Burns) |
| Код | Проект на диске, Monaco, чекпоинт git, zip |
| Деплой | Сгенерировать Dockerfile + скачать zip; **без** «опубликовано» |
| Монетизация | LLM-план + список артефактов; **без** биллинга |
| Интеграции | Builtin fetch/filesystem/browser; внешние — конфиг, не «подключено» |
| Скиллы | Либо markdown → system prompt, либо **скрыть** из навигации |
| Библиотека | Все артефакты всех воркспейсов |
| Админ | Пользователи, аудит, статистика, дефолты ИИ |
| Настройки ИИ | BYOK / выбор студийного прокси |

## 1. Чего в MVP **не** будет

- Реальные платежи, выплаты, биллинг, «кабинет автора».
- Удалённый Docker-деплой, push в registry, SSH, «опубликовано на хосте».
- Photoshop-lite / Figma-lite как редакторы слоёв ( holst, кисти, инспектор DOM).
- Premiere/Vegas NLE (бритва, LUT, 10–20 мин / 2-часовые фильмы).
- Мультиплеер, коллаборация, шаринг ссылок между аккаунтами.
- OAuth (Google/GitHub login).
- URL-роутинг `/w/[id]` — **опциональная W12**, не гейт MVP.
- Удаление `prototypes/` — отдельная зачистка после MVP.
- Магазин скиллов, импорт SKILL.md с URL, «купить скилл».
- Cursor-стиль клик-по-DOM в iframe превью.
- RAG/pgvector, BullMQ, Gitea, мультиагентный Analyst→Planner→Coder.
- Onboarding-тур, quest-режим, графики статистики заметок.

## 3. Данные и онтология

**Одна творческая единица = `Project`.**

- Контентный воркспейс: `origin = "workspace"`, `type` = film/book/music/app/universal.
- Код-проект: может остаться `origin = template|github|zip`. Рискованно сливать в один ряд без миграции. **MVP:** воркспейс типа «Приложение» при создании получает `rootPath` (шаблон на диске) **или** вкладка Код создаёт/открывает файлы **этого** `Project.id`, а не чужой `projects[0]`.
- Заметки: модель `Note` глобальная (блокнот). Привязка к воркспейсу — уже существующий `NoteLink`. Счётчик `counts.notes` в `workspace-shapes.ts` уже считает `noteLink`. UI вкладки Заметки это игнорирует — починить.
- Не плодить вторую таблицу «WorkspaceNote».
- `MOCK_WORKSPACES` оставить только в `scripts/seed-workspaces.ts` (опциональный сид демо) или удалить из импортов UI. `findWorkspace` не использовать в рантайме.
- Имена VibeFlow в комментариях схемы / zip-имени проекта — не блокер. Менять пачку строк, только если пользователь видит «VibeFlow» в UI (поиск: `vibeflow-project-` в `project-screen.tsx`).

## 4. Как вписывается шлюз ИИ (уже собрано)

- Провайдеры: `AiProvider` / `AiModel` / `ToolModelDefault` / `UserToolModel`.
- Админ задаёт платформенные ключи и дефолты инструментов (`AI_TOOL_IDS` в `src/lib/ai/tools.ts`).
- Пользователь может BYOK в Настройках ИИ.
- Резолв: `src/lib/ai/resolve.ts`. Вызовы: `src/lib/ai/connector.ts`.
- Не настроено → `UNCONFIGURED_TOOL_MESSAGE` / `GatewayError` по-русски.
- Агент-сервис (`mini-services/agent-service`) должен ходить в тот же шлюз (уже: `generateImage`/`synthesizeSpeech`/`resolveToolRoute`). Не возвращать z-ai.
- Инструменты агента **не** дублируют HTTP SDK в обход `src/lib/ai`.

```text
3. bun run dev            # Next :3000; агент: bun run dev:agent или POST /api/health/agent-service
4. Открыть http://localhost:3000
5. «Создать аккаунт» — первый пользователь = админ
6. Профиль → Админ-панель → Модели ИИ:
     провайдер openai_compatible или anthropic_compatible,
     ключ, модель chat + (по возможности) image/tts,
     дефолты инструментов agent/notes/image/tts
7. Воркспейсы → Создать → Книга «Тишина» → вкладка Чат:
     «Запиши заметку: маяк в тумане. Создай главу 1 пролога.»
8. Вкладка Заметки — заметка на месте после reload
9. Вкладка Документы — глава есть, текст редактируется и автосохраняется
10. (если image настроен) «Нарисуй обложку маяка» → Изображения / Дизайн
11. Экспорт: меню воркспейса или Деплой/Код → zip или WAV/WebM
```

Без ключей ИИ шаги 1–6 и создание воркспейса всё равно работают; шаг 7 должен показать русскую ошибку конфигурации, а не пустой чат.
