# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ) НА ПРОДУКТ «NARRATIVECORE»

## Версия 1.0 – MVP и план развития до версии 3.0

---

## 1. ОБЩИЕ ПОЛОЖЕНИЯ

### 1.1. Наименование продукта
NarrativeCore (рабочее название).

### 1.2. Назначение
Веб-приложение для писателей, сценаристов и геймдизайнеров, обеспечивающее:
- Создание и поддержание базы знаний вымышленного мира (сущности, связи, правила).
- Написание и структурирование книг, сценариев, нарративных документов.
- Контроль консистентности (канона) текста относительно базы знаний.
- Генерацию текстовых и иллюстративных материалов с помощью AI.
- Экспорт в издательские и веб-форматы.

### 1.3. Целевая аудитория
- Писатели-одиночки (основной сегмент MVP).
- Сценаристы сериалов, фильмов, подкастов.
- Геймдизайнеры нарративных игр.
- Небольшие творческие студии (от 2 до 10 человек) – целевая аудитория платной версии.

### 1.4. Бизнес-модель
Freemium: бесплатный тариф с ограничениями (1 проект, 500 сущностей, 50 глав, без AI). Платные тарифы Pro и Team (подписка). Дополнительная монетизация – пакеты AI-запросов.

## 2. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

### 2.1. Управление миром (база знаний)

#### 2.1.1. Сущности
- **Предустановленные типы:** персонаж, фракция, локация, предмет, событие, правило.
- **Пользовательские типы:** возможность создавать новые типы (например, «магическая школа», «технология», «раса»).
- **Поля сущности:**
  - Обязательные: id, name, description, type.
  - Типовые для каждого предустановленного типа (например, для персонажа: пол, возраст, статус, фракция, локация).
  - Динамические (пользовательские) поля в формате «ключ-значение» со следующими типами: строка, число, дата, ссылка на другую сущность.
- **Связи между сущностями:**
  - Направленные связи с типом (например, «контролирует», «союзник», «враг») и опциональной меткой.
  - Поддержка множественных связей.

#### 2.1.2. Каталог
- Страница со списком всех сущностей проекта, фильтрация по типу, поиск по имени.
- Карточка сущности: просмотр, редактирование, отображение связанных сущностей.
- Импорт существующего мира из текстового файла (.txt / .md) с интерактивной разметкой.

#### 2.1.3. Правила мира
- Хранение правил в виде структурированных записей (условие → следствие, числовые параметры, текстовое описание).
- Для MVP – только текстовое описание. Для полной версии – возможность использовать правила в проверке канона и AI-генерации.

### 2.2. Писательский редактор

#### 2.2.1. Редактирование глав
- WYSIWYG-редактор на основе Markdown (TipTap) с возможностью переключения в исходный код.
- Древовидное оглавление с возможностью drag-and-drop переупорядочивания глав.
- Автосохранение черновика каждые 30 секунд.
- Хранение истории изменений в рамках сессии (возможность отменить/повторить).

#### 2.2.2. Контекстная панель
- Автоматическое распознавание в тексте имён сущностей (по словарю проекта).
- Список упомянутых сущностей с быстрым переходом к их карточкам.
- Кнопка «Создать сущность из выделенного текста»: имя и описание подставляются из выделения, остальные поля заполняются пользователем.

#### 2.2.3. Сводка по главе
- Автоматическая генерация сводки при сохранении (на основе распознанных сущностей и ключевых предложений – простая эвристика).
- Редактирование сводки пользователем.
- Сохранение сводки в метаданных главы (используется для AI-контекста и проверок).

### 2.3. Проверка консистентности (канон)

#### 2.3.1. Подсветка в тексте
- **Жёлтая подсветка:** слово совпадает с именем сущности, но атрибуты, ожидаемые из контекста, не совпадают со значением в каталоге (например, персонаж мёртв по каталогу, но в тексте действует как живой).
- **Красная подсветка:** ссылка на имя сущности, отсутствующей в каталоге.
- Интерактивная подсказка при наведении: показывает имя сущности и причину конфликта.

#### 2.3.2. Панель проверки канона
- По нажатию кнопки «Проверить канон» сканируются все главы проекта.
- Выводится список потенциальных противоречий с указанием главы, фрагмента текста и предполагаемой сущности.
- Для полной версии (2.0) – семантическая проверка с использованием эмбеддингов и векторного поиска (поиск противоречий по смыслу, а не только по именам).

### 2.4. AI-генерация

#### 2.4.1. Генерация сущностей
- Выбор типа сущности (существующий или пользовательский).
- Опциональный текстовый промпт от пользователя (например, «создай хитрого торговца на чёрном рынке»).
- Отправка в LLM контекста: правила жанра, несколько примеров существующих сущностей того же типа, краткое описание мира.
- Вывод предзаполненной карточки сущности (поля, описание) – пользователь принимает или редактирует.

#### 2.4.2. Генерация сцены
- Пользователь вводит промпт (свободный текст) или выбирает элементы из каталога (персонаж, локация, предмет).
- Система собирает контекст:
  - Для MVP: карточки выбранных/упомянутых сущностей, последнюю главу (если применимо), правила жанра.
  - Для полной версии (2.0): дополнительно RAG-поиск по всем главам проекта (семантически близкие фрагменты).
- LLM генерирует текст (от 300 до 2000 слов, настраивается).
- Результат вставляется в текущую позицию курсора в редакторе.

#### 2.4.3. Генерация иллюстраций
- Выделение фрагмента текста (или всей главы) → нажатие кнопки «Сгенерировать иллюстрацию».
- Формирование промпта: исходный текст + выбранный стиль (реалистичный, аниме, киберпанк, фэнтези) + дополнительные параметры (соотношение сторон, разрешение).
- Асинхронная генерация через Replicate API / DALL-E (задача в очереди).
- Уведомление пользователя по WebSocket о готовности.
- Изображение вставляется в главу (или сохраняется в галерее иллюстраций проекта).

#### 2.4.4. Ограничения и безопасность
- Для бесплатного тарифа AI-генерация недоступна.
- Для Pro-тарифа: квота на количество запросов в месяц (100 текстовых, 25 иллюстраций). Дополнительные пакеты покупаются отдельно.
- Все запросы логируются для контроля злоупотреблений.

### 2.5. Визуальный граф связей

#### 2.5.1. MVP (базовый)
- Отображение всех сущностей проекта в виде узлов, связей между ними – рёбер.
- Управление: перетаскивание узлов, масштабирование, панорамирование.
- Двойной клик по узлу → открытие карточки сущности.
- Фильтрация отображаемых типов сущностей (галочки).

#### 2.5.2. Полная версия (2.0)
- Редактирование связей из графа (добавление/удаление рёбер, изменение типа связи).
- Подсветка пути между двумя выбранными сущностями.
- Экспорт графа в изображение.
- Импорт графа из JSON (например, из Obsidian).

### 2.6. Версионирование

#### 2.6.1. Автоматические бэкапы
- При каждом сохранении проекта (или через каждые 10 изменений) создаётся снимок всего проекта (каталог + главы + настройки).
- Хранится до 50 последних авто-бэкапов или за последние 30 дней (что больше).

#### 2.6.2. Ручные версии
- Пользователь может в любой момент сохранить версию с комментарием (например, «Перед переработкой финала»).
- Список версий с возможностью просмотра и восстановления (восстановление заменяет текущее состояние проекта).

#### 2.6.3. Полная версия (командная)
- Интеграция с Git (экспорт/импорт в репозиторий).
- Визуальное сравнение версий (side-by-side diff для сущностей и глав).

### 2.7. Экспорт

#### 2.7.1. Форматы (MVP)
- **JSON:** полный дамп всех данных проекта (сущности, связи, главы, настройки, метаданные). Для резервного копирования и машинной обработки.
- **Markdown-книга:** один файл .md со всеми главами в порядке следования + глоссарий (список сущностей с описанием).
- **Статическая HTML-вики:** папка с HTML-файлами, содержащая каталог сущностей и главы, с навигацией.

#### 2.7.2. Форматы (полная версия)
- **EPUB:** электронная книга для читалок.
- **PDF:** типографская вёрстка.
- **Twine / Ink:** экспорт в форматы интерактивных историй (с ветвлениями и состояниями).
- **Docx:** для совместимости с Microsoft Word.

### 2.8. Пользовательские настройки проекта
- Название, краткое описание, жанр (выбор из списка или свой вариант).
- Режим приватности: приватный (только владелец), по ссылке (доступ на чтение), публичный (виден в галерее).
- Настройки AI: выбор модели (gpt-4o-mini / gpt-4o), параметры генерации (температура, максимальная длина), стиль иллюстраций по умолчанию.
- Подключение собственного API-ключа OpenAI (для Pro-тарифа – возможность использовать свой ключ и не тратить квоту).

## 3. НЕФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

### 3.1. Производительность
- Время ответа API (95% запросов) – не более 500 мс для операций CRUD, не более 2 с для экспорта.
- Генерация AI – не более 15 с (текст), не более 30 с (иллюстрация). При превышении – возврат частичного результата или ошибка с предложением повторить.
- Рендеринг графа с 500 узлами – не более 1 с на загрузку, FPS > 30 при панорамировании.

### 3.2. Безопасность
- Аутентификация через JWT (Access + Refresh токены), хранение паролей с bcrypt.
- Все API-запросы, кроме /auth, требуют валидного токена.
- Защита от CSRF, XSS, SQL-инъекций (стандартные механизмы NestJS и TypeORM).
- HTTS на всех средах, кроме локальной разработки.

### 3.3. Надёжность и отказоустойчивость
- Автоматическое резервное копирование БД каждые 24 часа (хранится 30 дней).
- При сбое AI-генерации – повторный запрос (максимум 3 раза) с экспоненциальной задержкой.
- Возможность восстановления проекта из последнего авто-бэкапа администратором.

### 3.4. Масштабируемость
- Бэкенд – горизонтальное масштабирование через балансировщик (Nginx), сессии вынесены в Redis.
- Очереди BullMQ позволяют распределять задачи генерации между несколькими воркерами.
- База данных – репликация «главный-подчинённый» для чтения (при росте нагрузки).

### 3.5. Удобство использования
- Интерфейс должен быть интуитивно понятным без чтения документации (однако туториалы и подсказки присутствуют).
- Адаптивная вёрстка (десктоп, планшет; мобильная версия – в полной версии).
- Поддержка горячих клавиш (Ctrl+S, Ctrl+Z, Ctrl+Shift+S – сохранить версию и т.д.).

### 3.6. Совместимость
- Браузеры: последние версии Chrome, Firefox, Safari, Edge.
- Экспортируемые форматы должны открываться стандартными программами (Markdown – любым редактором, HTML – браузером, JSON – любым парсером).

## 4. ОГРАНИЧЕНИЯ ПРОЕКТА (MVP)

В MVP не входят следующие функции (они отложены на полные версии):

- Коллаборативная работа (совместное редактирование, комментарии, права доступа).
- Семантическая проверка канона с RAG (только имённая).
- Экспорт в EPUB, PDF, Twine, Ink.
- Мобильная версия (только десктоп/планшет).
- Импорт из других систем (Obsidian, Scrivener, Word).
- Визуальное сравнение версий.
- Пользовательские типы связей (только предустановленные: «союзник», «враг», «контролирует», «находится в», «владеет»).
- Векторная база данных и RAG (появляется в версии 2.0).

## 5. КРИТЕРИИ ПРИЁМКИ MVP

Выполнение всех функциональных требований, перечисленных в разделе 2, с пометкой «MVP» (раздел 2.1 – 2.7, кроме функционала, явно отнесённого к полной версии). Дополнительные критерии:

1. Пользователь может зарегистрироваться, создать проект, добавить 10 сущностей и написать 5 глав, ни разу не столкнувшись с ошибкой.
2. Проверка канона корректно находит не менее 90% конфликтов типа «мёртвый персонаж действует» и «неизвестная сущность».
3. Генерация сцены с промптом «напиши диалог» даёт осмысленный текст, связанный с предоставленными сущностями.
4. Экспорт в HTML-вики открывается в браузере и содержит все главы и каталог.
5. Время загрузки страницы каталога с 500 сущностями не превышает 2 секунд.

## 8. ГЛОССАРИЙ

- **Сущность** – любой объект вымышленного мира (персонаж, фракция, локация и т.д.).
- **Канон** – совокупность неопровержимых фактов мира, зафиксированных в каталоге.
- **RAG** – Retrieval-Augmented Generation. Метод дополнения промпта релевантными фрагментами из базы знаний.
- **Эмбеддинг** – векторное представление текста, используемое для семантического поиска.
- **Сводка главы** – краткое структурированное описание (участники, локация, ключевые события, итог).
